Highside AWS CLI + K9s Setup (UMAI & CPAS)

BLUF: This is the consolidated, Eagle-specific guide for getting AWS CLI + K9s/kubectl access working on your highside laptop. It replaces or acts as a renewed point of reference for the floating "AWS-CLI-set-up-documentation" file (Word/PDF passed around via Teams/email) — this page is now the source of truth referenced from the Hub and from Eagle K9s Cheat Sheet.

This doc combines the references from AWS-CLI-set-up-documentation and the highside confluence doc. If you need to reference the original copies, you can find them here:

Prerequisites

  • Highside laptop with Heightened Account (HA) already created (see Requesting Access section below if you don't have one yet)
  • Cluster access (heightened devrole pt 2 following this) — you should have this automatically.
  • For CLI-distillery / conda / Horizon proxy setup, that's a separate flow — see Get your Eagle Development Setup Ready Highside instead. This page is only about AWS CLI + K9s/kubectl cluster access.
  • It would help to have your opencode setup already for troubleshooting!

The base AWS CLI install steps below are adapted from Elevance's generic Confluence page ("How to setup AWS CLI on MacOS", owned by their platform team, used by many app teams beyond just Eagle). That page's own step numbering has a known bug (two different steps are both labeled "12"), and a previous version of this guide referenced it by step number ("skip steps 10-11") — that reference no longer matches and has been dropped here. Don't cross-reference Confluence by step number — its numbering can and does drift. If you need to go to Confluence directly, look for the heading text, not a step number.

Part 1: AWS CLI Setup

1. Install Homebrew

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

2. Install Python 3.9

Pin Python 3.9 specifically — the generic Confluence doc just says "install python3" with no version pin, but the Eagle virtual environment setup expects 3.9 and things may not work as expected on other versions.

brew install python@3.9

3. Create highside aws_cert folder

Go to this link highside (wellpoint folder) and download the Aws_Cert folder which will include:

  • samlapi.py
  • root.pem — the copy from Get your Eagle Development Setup Ready Highside is not the one you need for this folder, you need the one from wellpoint folder.
  • updateCerts.sh

4. Create and activate a virtual environment

cd ~/aws_cert
pip install --user virtualenv --cert root.pem
/Users/{AMxxxx}/Library/Python/2.7/bin/virtualenv -p python3.9 sandbox
cp samlapi.py root.pem updateCerts.sh sandbox/
cd sandbox
source bin/activate

5. Install AWS CLI

pip install --upgrade awscli --cert root.pem
aws --version

6. Configure AWS CLI

Run aws configure once to create ~/.aws/config, then edit that file with nano ~/.aws/config directly to add the Distyl-specific profile blocks below exactly as written (except your own username):

[profile elv-distyl-gold]
aws_secret_access_key = default
aws_access_key_id = default
region = us-east-1
output = json
role_arn = arn:aws:iam::307946675711:role/gld-apm1080697-devrole
source_profile = elv-distyl-gold

[profile crln-distyl-gold]
aws_secret_access_key = default
aws_access_key_id = default
region = us-east-1
output = json
role_arn = arn:aws:iam::307946675711:role/gld-apm1082082-devrole
source_profile = crln-distyl-gold

7. Install Python dependencies

pip3 install boto boto3 requests configparser bs4 --cert root.pem

8. Run updateCerts.sh

chmod +x updateCerts.sh
./updateCerts.sh

This appends root.pem to the various cacert bundles inside your virtual environment's installed packages.

9. Get your HA username + 10-hour password

  1. Log into CyberArk (have to use this link highside) — username is your AM… and follow okta login.
  1. Store the temporary password & account name in macOS Keychain for the script to access:

    Keychain Access → File → New Password Item → name it USHA, account = your HA account, password = today's temporary password. See image:

NOTE: Do not change any other thing in this command except for the username and password
(see image above, username is starting from AN... and not AM. The password is
something that you can copy once you click on the show button).

  1. This password expires roughly every 10 hours — you'll need to update the Keychain entry (and re-run samlapi.py below) each time it expires (every time you access k9s or aws).

10. Run samlapi.py

Make sure you are in virtual environment.

Go to you virtual env folder and then activate the virtual env.

  • source bin/activate

For UMAI UAT:

python3 samlapi.py 'ANXXXXXAD@us.ad.wellpoint.com' "$(security find-generic-password -a USERNAME -s USHA -w)" arn:aws:iam::738234568511:role/gld-apm1080697-devrole elv-distyl-gold us-east-1

For CPAS UAT:

python3 samlapi.py 'ANXXXXXAD@us.ad.wellpoint.com' "$(security find-generic-password -a USERNAME -s USHA -w)" arn:aws:iam::738234568511:role/gld-apm1082082-devrole crln-distyl-gold us-east-1

Note this uses account 738234568511, while the Confluence docs sometimes use 307946675711 for the same role name. Use the one starting with 732…

NOTE

  • Replace the username and password with yours that you would obtain from the
    CyberArk website.
  • If you get SSL related errors, do: export AWS_CA_BUNDLE="path to your root.pem file”
  • The Password changes every 10hrs or so, so one would have to run the command
    every time to get access to the cluster

Add login types

Add login-uat/login-cpas shell functions that read the password from Keychain automatically instead of typing the command above each time.

Do nano ~/.zshrc

Then add this to it: 

login-uat() {
	local username='ANXXXXAD'
	local user='ANXXXXAD@us.ad.wellpoint.com'
	local role_arn='arn:aws:iam::738234568511:role/gld-apm108097-devrole'
	local app='elv-distyl-gold'
	local region='us-east-1'
	
	local pass="${1:-}"
	if [[ -z "$pass" ]]; then
		if ! pass=$(security find-generic-password -a "$username" -s USHA -w 2>/dev/null); then
			echo "Keychain entry not found for $user (service USHA)" >&2
			return 1
		fi
	fi

	python3 samlapi.py "$user" "$pass" "$role_arn" "$app" "$region"
}

login-cpas() {
	local username='AN849445AD'
	local user='AN849445AD@us.ad.wellpoint.com'
	local role_arn='arn:aws:iam::738234568511:role/gld-apm1082082-devrole'
	local app='crln-distyl-gold'
	local region='us-east-1'
	local pass

	if ! pass=$(security find-generic-password -a "$username" -s USHA -w 2>/dev/null); then
		echo "Keychain entry not found for $user (service USHA)" >&2
		return 1
	fi

	python3.9 samlapi.py "$user" "$pass" "$role_arn" "$app" "$region"
}

Restart your terminal and then in bash you can use commands like “login-cpas” and “login-umai” to get the relevant tokens. Prerequisite is to replace your USERNAME and add USHA to keychain setup.

11. Verify AWS CLI access

aws s3 ls --profile elv-distyl-gold

Part 2: K9s / kubectl Setup

Install kubectl and k9s

brew install kubectl k9s

Set up kubeconfig

Download the relevant kubeconfig files from here (accessible highside) and point KUBECONFIG at it:

ClusterKubeconfig
UMAI UATdistyl_gold_config.yaml
CPAS UATcarelon-distyl-non-prod.yaml
UMAI Platinum (read-only)platinum-read-config.yaml
CPAS Platinum (read-only)cpas-platinum-read-config.yaml

Try one and then the rest.

For instance,

Get link to the file for UMAI UAT: distyl_gold_config from the link above.

Update the KUBECONFIG to point to this kube configuration when accessing UMAI UAT.

export KUBECONFIG='path_to_virtual /distyl_gold_config.yaml’

This is the generic command for all of them:

export KUBECONFIG='path_to_virtual_env/CONFIG_NAME.yaml'

Once you’ve done that for one of them, try this: 

aws eks update-kubeconfig --name distyl-gold --region us-east-1 --profile elv-distyl-gold
kubectl get pods -n umsvc-perf-gold

Once this works, run k9s and see Eagle K9s Cheat Sheet for namespace/pod navigation and shortcuts. You can also configure it for the rest of the clusters now.

Troubleshooting

SSL errors (SSLCertVerificationError, self-signed certificate in certificate chain) — make sure you ran updateCerts.sh (step 8), or export AWS_CA_BUNDLE="path to your root.pem" directly.

samlapi.py fails with IndexError: list index out of range on awsroles[0].split(',')[0] — this means your AWS roles list came back empty, i.e. you're missing the K8s cluster AD group access (see Requesting Access above). Heightened account alone isn't enough.

AssumeRole AccessDenied when running aws eks update-kubeconfig — if you get an AccessDenied error on sts:AssumeRole (AWS CLI trying to assume a role via a stale/personal IAM session instead of the org role), re-run samlapi.py (step 10) and redo the setup from there — this resets which role gets assumed and usually clears the error. Source

10-hour password expired — CyberArk passwords expire roughly every 10 hours. Update the Keychain USHA entry with the new password and re-run samlapi.py (step 10).
